Redesigning the inputs

Your answers to the first 2.3 page, worked through: separate objects for the two kinds of prior, samples treated as a realisation of the PDF, one integral behind every continuous input, binned measurements with a response, and classifiers from first principles. Numbers come from two experiments in notes/review/experiments/.

§1

Two kinds of prior, two objects

Two different things are both called "the prior" today:

PopulationPrior

What it is
A distribution over the population $\rho$, the thing we infer.
Today
Everything in pastry.priors (Dirichlet, trees, GP, random walk…), base class Prior.
Change
Rename the base class so it can't be confused with the interim prior.

InterimPrior

What it is
One fixed density $\pi(z)$ that someone else used: to compute catalogue posteriors, draw samples, or train a classifier. Never inferred; only divided out.
Today
An argument taking "flat", a bare array (mass or density, read differently by different constructors) or a callable.
Change
One object, accepted everywhere, with the same meaning everywhere.

The same kind of object (a fixed density over $z$) appears elsewhere too: the base measure of Dirichlet and Pólya-tree priors, the measure density (#21), the injection distribution for selection (#10), and the true population in simulate. One underlying class (say pastry.Density) with arguments named by role (interim=, base_measure=, measure=) would cover all of them; InterimPrior could be that class or a thin named alias.

§2

Samples: a realisation, not a histogram

You're right: no per-object density estimate is needed. The model already says what to compute, the bin (or basis) average of the likelihood:

$$L_{ik} = \int p(d_i\mid z)\,\phi_k(z)\,dz, \qquad \phi_k = \frac{\mathbf 1_{B_k}}{v_k}\ \text{(histogram bins) or a hat function (B-splines, #5)}.$$

Samples $z_{is}$ from the posterior under $\pi$ give that integral directly, because $p(d_i\mid z) = Z_i\,p(z\mid d_i)/\pi(z)$:

$$L_{ik} = Z_i \int p(z\mid d_i)\,\frac{\phi_k(z)}{\pi(z)}\,dz \;\approx\; \frac{Z_i}{S}\sum_{s=1}^{S} \frac{\phi_k(z_{is})}{\pi(z_{is})}.$$
  • $Z_i$ is a row scale and drops out. For histogram bins each sample contributes $1/(v_k\,\pi(z_{is}))$ to its bin; for hat functions it splits fractionally between neighbours. Same formula either way.
  • Pointwise $\pi(z_{is})$, not $\Pi_k$. Today's code divides counts by the interim bin mass, which is right only if $\pi$ is flat inside each bin. The pointwise form is exact (and needs InterimPrior.pdf).
  • Likelihood samples are the case $\pi$ = flat in $z$ (weights 1). They need a likelihood that integrates over $z$; e.g. a parallax likelihood in distance does not.

Is "N given p, not p" fine? Yes, with a sample-size condition

$\hat L_i\cdot\rho$ is unbiased for $p(d_i\mid\rho)$. But the posterior uses its log, and $\mathbb E[\log X] < \log\mathbb E[X]$. Per object the log-likelihood is low by about half its relative variance $V_i(\rho)/2$, and this adds up over objects:

$$\Delta\log\mathcal L(\rho) \approx -\tfrac12\sum_i V_i(\rho),\qquad V_i(\rho) \approx \frac{1}{S}\left(\frac{\mathbb E_{q_i}[(\rho/\pi)^2]}{\mathbb E_{q_i}[\rho/\pi]^2}-1\right).$$

Two consequences. It grows like $N/S$. And it depends on $\rho$: it is zero where $\rho \propto \pi$ over each object's posterior, and large where $\rho$ puts mass the samples rarely visit, so it pulls the posterior towards the interim prior. Zero-count bins are the extreme case of the same error, not a separate problem.

So here you need roughly $S \gtrsim N$ samples per object to keep the error near the answer below one unit of log-likelihood. This is the precision requirement known from gravitational-wave population inference, which uses exactly this estimator. What pastry should add:

  • a diagnostic: $\sum_i \hat V_i(\rho)$ computed from the samples at posterior draws, with a warning when it exceeds about 1 (cheap: one pass over the stored counts);
  • a per-object effective sample size under the fitted population (not just under the interim prior, as today);
  • optionally, a Bayesian floor for empty bins: treating the bin fractions $q_i$ as unknown with $q_i \mid c_i \sim \mathrm{Dir}(c_i + a\,\pi)$ gives $\hat L_{ik} \propto c_{ik}/\pi_k + a$, a principled constant floor rather than an arbitrary one.
§3

One integral, three integrators

Your samples point unifies the continuous inputs. Gaussians, functions, distribution objects and samples all compute the same quantity, $\int f_i(z)\,\phi_k(z)/\pi(z)\,dz$; they differ only in how the integral is done:

What you haveIntegratorError control
a CDF (Gaussian, correlated Gaussian in 1-D/2-D, scipy distribution in 1-D)exactmachine precision
a density you can evaluate (callable, logpdf, correlated Gaussian in ≥ 3-D)adaptive quadrature or quasi-Monte Carlo (#23, #25)tolerance
samplesMonte Carlo (§2)$N/S$ diagnostic

Proposal: one constructor for densities (name to pick: from_density, from_function, from_pdf) that accepts a vectorised callable, a list of callables, or a list of distribution objects, and uses the CDF whenever one exists; from_gaussian stays as a named fast path and from_samples as the Monte Carlo path. All three share kind/interim, the basis $\phi_k$, the bins and measure, and the outside-support bookkeeping (#18).

§4

Binned measurements and the response

Terminology first, since this is what made from_response opaque:

  • Truth bins $k = 1..K$: where the population lives (pastry's usual bins).
  • Measurement bins $j = 1..J$: the measurement is only known to fall in one of these. Physics calls them reco bins; for a classifier they are predicted classes or score bins.
  • Response $R_{jk} = P(\text{measured in } j \mid \text{true } k)$. Column sums $\epsilon_k \le 1$ are the efficiency (objects never measured).
  • Data: counts $n_j$. Every object in bin $j$ has the same likelihood row $R_{j\cdot}$, so pastry stores $J$ rows weighted by $n_j$. Fitting $\rho$ is "unfolding".

Proposal: a Response object, built either from a simulation (true bin and measured bin of each simulated object, plus how many were generated per true bin) or from labelled data (§5). It records the counts it was estimated from, so it carries its own uncertainty: one Dirichlet per column. Likelihoods.from_binned(counts or measured values, response) replaces from_response, with real truth-bin geometry instead of defaulting to categories. §7 shows how to handle the uncertainty properly.

§5

Classifiers from first principles

The setting. A labelled training set has class prevalences $\pi^{\rm tr}$. A target set is unlabelled, with unknown prevalences $\rho$. We want $\rho$ (known in machine learning as quantification under label shift).

The one assumption that matters: label shift. The classes look the same in both sets, $p_{\rm target}(x\mid c) = p_{\rm train}(x\mid c)$; only the mix changes. Then the target is exactly pastry's model,

$$p_{\rm target}(x_i) = \sum_c \rho_c\,p(x_i\mid c),\qquad L_{ic} = p(x_i\mid c).$$

We can't evaluate $p(x\mid c)$ for high-dimensional $x$. A classifier compresses $x$ into a score $s(x)$, and label shift holds for any function of $x$, so $L_{ic} = p(s_i\mid c)$ is a valid likelihood for any classifier, good or bad. A bad classifier loses information; it does not bias anything. The question is only how to get $p(s\mid c)$:

Route A: Bayes' rule

Idea
If $s_c = p_{\rm train}(c\mid x)$ exactly, then $p(x\mid c) \propto s_c/\pi^{\rm tr}_c$. This is from_classifier today; its maximum-likelihood fit is the EM of Saerens et al. (2002), often called SLD/EMQ.
Needs
Label shift, calibration, and the classifier's effective training prior (class weighting or balanced batches change it).
Bonus
A calibrated probability vector is a sufficient statistic for the class, so nothing is lost.

Routes B and C: measure it

Idea
Estimate $p(s\mid c)$ on a labelled validation set from the training distribution: bin the score, count per class. That is a response matrix (§4). Hard labels give the confusion matrix (B; "adjusted classify-and-count", BBSE). Finer score bins (C) keep more information.
Needs
Label shift and a representative validation set. Not calibration, and not $\pi^{\rm tr}$.
Cost
The validation set is finite, so $R$ is uncertain, and more bins means noisier columns.

Recalibration (e.g. temperature scaling on the validation set, then route A) is a parametric version of route C: a smooth model for $p(s\mid c)$. It can be more efficient, but its uncertainty should be propagated too, which today's practice usually skips.

  • Classify-and-count is biased towards the training mix even with a perfect classifier. Never a default.
  • Route A is the most precise when its assumptions hold (rms 0.013 vs 0.024–0.032) and badly biased, with zero coverage, when they don't.
  • Routes B and C give identical results under any temperature. Miscalibration is a monotone transform of the score, which doesn't change quantile bins. They never use $\pi^{\rm tr}$.
  • Nothing fixes a label-shift violation. But routes B/C can detect one: the target's score histogram must equal $\sum_c\hat\rho_c\,p(s\mid c)$, a free posterior predictive check (the explorer's second panel).

§7

An uncertain response: draws or parameters?

A response estimated from finite data is uncertain. Ignoring that (plugging in $\hat R$) gives intervals that are too narrow. There are three ways to include it:

  • Joint, by averaging over draws. Draw $R^{(m)}$ from its Dirichlet posteriors and use $\log\frac1M\sum_m p(n\mid\rho,R^{(m)})$. This is what #10 adopted for selection draws.
  • Cut. Fit separately for each draw and pool the posteriors (the data don't update $R$).
  • Parameters. Treat $R$ as unknown alongside $\rho$. With Dirichlet columns this is fully conjugate: Gibbs alternates the class of each target object, $\rho$, and each column of $R$.

Averaging over draws breaks down once $R$ has many free numbers. With 2000 target objects, each draw's likelihood is sharply peaked, so the average is dominated by the luckiest draw, and more draws help only slowly. Treating $R$ as parameters is exact, cheap here (conjugate) and the most precise.

This reaches back to #10. The selection plan uses the same "joint by averaging over draws" default, so it has the same failure mode whenever the data constrain $S$ more tightly than the draws cover. The fix carries over: treat selection as parameters (conjugate Beta per bin for injections, or NUTS for the smooth model), keeping draw-averaging only with an effective-draw diagnostic. To revisit when we design selection inputs.

API sketch (for discussion)

Classifiers and unfolding under the redesign
# Route A: calibrated probabilities, the training prior made explicit
lk = Likelihoods.from_posteriors(p, Bins.categories(labels),
                                 interim=InterimPrior.from_masses(pi_train))

# Routes B/C: a response learned from labelled validation data
resp = Response.from_labelled(val_scores, val_labels,
                              measurement_bins=10)      # quantile bins of the score; 2 = confusion matrix
lk = Likelihoods.from_binned(target_scores, resp)       # bins the target scores into counts
res = pastry.infer(lk, Dirichlet(1))                    # R sampled jointly (Gibbs), by default
res.check()                                             # includes the score predictive check

# Unfolding: the same objects, built from a simulation
resp = Response.from_simulation(true_value, measured_value, truth_bins,
                                measurement_bins, n_generated)
lk = Likelihoods.from_binned(observed_counts, resp)

from_classifier becomes either a documented alias of route A or is removed in favour of the two paths above. Open for multi-class: how to bin a probability vector into measurement bins (predicted class × confidence quantiles is the simple choice).
