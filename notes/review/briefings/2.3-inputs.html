Every Likelihoods.from_* conversion: the math it implements, the code path, its numerical choices, what it guards against, and what the inputs audit found. File: likelihoods.py (1076 lines).

§0

Many doors, one representation

Every constructor ends in the same object: a matrix of bin-averaged likelihoods $L_{ik}\propto p(d_i\mid z_i\in B_k)$ with rows scaled to a maximum of one, per-row log-scales, weights, and an optional selection function. Downstream code never knows where the data came from (it is recorded in meta["source"]).

§1

Raw matrices

likelihoods.py · __init__ (l. 190), _normalise_linear (l. 947), _normalise_log (l. 979), _init_from_parts (l. 225)
  • Validation: finite, non-negative, 2-D, $K\ge2$, columns match bins.K.
  • Representation. "density" (default): each value is the likelihood averaged over the bin. "mass": the likelihood integrated over the bin (e.g. CDF differences); it is divided by the bin volume. Only matters with unequal bins.
  • Log input (log=True or from_log): rows are exponentiated after subtracting their maximum, so log-likelihoods of −104 are fine; −∞ marks impossible bins.
  • Sparse input stays sparse (CSR, copied so the caller's matrix is never modified).
  • Empty rows (zero likelihood in every bin) raise, or are dropped with a warning under drop_empty=True; per-object metadata follows the surviving rows.

Audit: I-8 (to_sparse(rtol>1) empties every row), I-11 (zero objects accepted), I-14 (internal arrays writable and shared).

§2

Gaussian errors

likelihoods.py · from_gaussian (l. 600), _log_gauss_bin_mass (l. 120)
$$L_{ik}=\frac{1}{v_k}\Big[\Phi\Big(\frac{b_k-d_i}{\sigma_i}\Big)-\Phi\Big(\frac{a_k-d_i}{\sigma_i}\Big)\Big]\qquad(B_k=[a_k,b_k]).$$
  • Exact (no quadrature), computed in log space with log_ndtr. When the bin lies above the measurement, the code uses the mirror-image tail, $\Phi(-a)-\Phi(-b)$, so a bin 40σ away still gets a finite log-likelihood instead of $1-1=0$.
  • N-D grids: one 1-D mass per axis, combined by an outer sum in log space: independent errors per axis (diagonal covariance).
  • Remembers each object's mean and σ (meta), so sample_values can draw exact truncated-Gaussian values inside a bin.
likelihoods.py:120 · tail-stable log of a Gaussian bin mass 
a, b = (lo - mu) / sig, (hi - mu) / sig
flip = a > 0                                   # bin above the mean: use the mirrored upper tail
a2, b2 = np.where(flip, -b, a), np.where(flip, -a, b)
lb, la = special.log_ndtr(b2), special.log_ndtr(a2)
out = lb + np.log1p(-np.exp(la - lb))          # log(Φ(b) − Φ(a)) without cancellation

Correlated errors (decision #2)

For a per-object covariance $\Sigma_i$ the bin average is a rectangle probability of a correlated Gaussian. Options: (i) exact bivariate CDFs in 2-D (Drezner–Wesolowsky / Genz) and quasi-Monte Carlo beyond; (ii) sub-cell Gauss–Legendre on the density with adaptive refinement where $\Sigma_i$ is narrow; (iii) rotate each object into its principal axes and integrate there. (ii) is the simplest to make general and reuses from_function's machinery; (i) is fastest and exact for the common 2-D case.

Audit: I-10 (ill-shaped mean silently reshaped; sigma ambiguous when N equals the number of axes), I-15 (relative precision lost when σ ≫ bin width).

§3

Posteriors and the interim prior

likelihoods.py · from_posteriors (l. 433), _interim_masses (l. 85), _check_posterior_representation (l. 997)

Most photo-z codes, classifiers and per-object fits report posteriors computed with some prior $\pi$. With posterior masses $P_{ik}$ and interim masses $\Pi_k=\int_{B_k}\pi$,

$$P_{ik}\propto L_{ik}\,\Pi_k\quad\Longrightarrow\quad L_{ik}\propto P_{ik}/\Pi_k$$

(exact if $\pi$ is constant within bins, the same flat-within-bin assumption as everywhere else). interim_prior has no default on purpose: "flat" (uniform density in the bin coordinate), an array per bin, or a callable density integrated by sub-bin quadrature. Arrays are read in the same representation as the posteriors unless interim_representation says otherwise; the constructor warns when rows only integrate to one under the other representation.

Explore: what goes wrong without the division

3000 objects on 12 log-spaced bins, photo-z-like errors σ = 0.08(1+z). Their posteriors are computed under an interim prior, then turned back into likelihoods four ways and fitted (maximum likelihood). Curves are densities per unit ln z. Changes apply on release.

truthcorrect: P ÷ Πposteriors used as likelihoodsinterim density read as massposterior density read as mass

Using posteriors as likelihoods counts the interim prior twice and drags the population toward it: with the peaked interim prior the fit lands 0.20 from the truth, against 0.065 for the correct conversion (which itself carries statistical noise and some binning bias). The two representation mix-ups leave a factor of the bin width in every likelihood row. Each object only feels how that factor changes across its own likelihood (×1.4 per bin here), so the damage is moderate in this example (0.077 and 0.109), and it grows with broader likelihoods or steeper changes in bin width.

Audit: I-1 (major: from_function(kind="posterior") reads an array interim prior as densities while from_distributions reads it as masses), I-9 (representation check skipped for small-unit bins), I-13, I-17.

§4

Posterior samples

likelihoods.py · from_samples (l. 518), _bin_samples (l. 1024)
$$L_{ik}\propto\frac{c_{ik}}{\Pi_k},\qquad c_{ik}=\sum_{s\in B_k}w_{is}\quad(\text{weighted count of object }i\text{'s samples in bin }k).$$
  • Ragged sample lists and importance weights are supported; N-D grids take (S, ndim) samples.
  • Per object it records the effective sample size $(\sum w)^2/\sum w^2$ and the fraction of samples outside the bins.
  • Stored sparse when fewer than 30% of entries are non-zero (narrow posteriors on many bins).
  • Warns when the median effective sample size is below min_samples (20).

Explore: how many samples per object?

500 objects on 20 bins over [0, 3], Gaussian errors σ, flat interim prior. Each object provides S posterior samples. Left: one object's exact likelihood vs its histogram. The readout compares maximum-likelihood fits from exact and histogrammed likelihoods. Changes apply on release.

The damage comes from empty bins: a bin with no samples gets likelihood exactly zero, so the object is declared impossible there. With narrow posteriors and few samples, many objects exclude their own true bin, and the fit becomes too narrow and too confident. Smoothing (add a small floor, a kernel per sample, or soft assignment to neighbouring bins with B-spline weights) fixes most of it; see §9.

Audit: I-23 (no smoothing, and the warning looks only at the median effective sample size).

§5

Functions and distributions

likelihoods.py · from_function (l. 753), from_distributions (l. 674), _subbin_points (l. 58)

from_function(func, bins) evaluates a vectorised (log-)likelihood at Gauss–Legendre points inside every bin (n_sub per axis, tensor products on grids) and averages: $L_{ik}\approx\sum_jw_j\,p(d_i\mid z_{kj})$, in log space with logsumexp when log=True. This is the general route for correlated N-D errors, non-Gaussian likelihoods, or anything you can evaluate. from_distributions takes one SciPy-like object per object: exact CDF differences in 1-D when a cdf exists, otherwise the same quadrature on logpdf/pdf. Both accept kind="posterior" with an interim prior.

Explore: quadrature error vs likelihood width

Worst relative error of the Gauss–Legendre bin average of a Gaussian likelihood (over measurement positions, bins holding at least 1% of the peak), against σ in units of the bin width h. Defaults: from_function uses 3 points per bin, from_distributions 5.

1 point3 points (from_function)5 points (from_distributions)9 points

A few fixed points per bin cannot resolve a likelihood much narrower than the bin. With 3 points (the from_function default) the worst entry is off by 5% at σ = h/4 and 70% at σ = h/10; 5 points are good to 0.04% at h/4 but fail in the same way at narrower widths. A fix is adaptive refinement (subdivide a bin until its average converges), or analytic forms where they exist.

Audit: I-1 (major, see §3), I-2 (CDF path cancels in the upper tail: objects 7–8σ below the bins get empty rows), I-3 (pdf path exponentiates before averaging and underflows), I-4 (the 3-point default).

§6

Unfolding: response matrices

likelihoods.py · from_response (l. 815)

In unfolding the data are counts $m_b$ in reconstructed bins and the detector is a response matrix. Every event observed in reco bin $b$ has the same likelihood row, so the data compress to one row per reco bin with weight $m_b$:

$$L_{bk}=R_{bk}=p(\text{reco }b,\ \text{observed}\mid\text{true }k),\qquad w_b=m_b .$$
  • Default convention: $R$ includes the efficiency, so its columns sum to $\epsilon_k\le1$; $\epsilon$ is attached as a selection function in on_measurement mode (the rows already contain it; only the normaliser is added).
  • Migration-matrix convention: pass columns summing to one plus efficiency=eps; rows become $R_{bk}\epsilon_k$.
  • Columns summing to more than one raise (they cannot be probabilities); an explicit efficiency with non-normalised columns warns (efficiency counted twice). Reco bins with zero counts are dropped.

This is exactly the D'Agostini/IBU setup; the maximum-likelihood fit is IBU's fixed point (§6 of step 2.1), with the KKT certificate and full posterior uncertainty on top.

§7

Quantification: classifier outputs

likelihoods.py · from_classifier (l. 894)

A classifier trained with class prevalences $\pi^{\rm train}$ outputs $p_{ic}\propto L_{ic}\,\pi^{\rm train}_c$ if it is calibrated. Dividing by $\pi^{\rm train}$ recovers likelihoods, and inferring $\rho$ on a test set with different prevalences is the prior-shift problem (EMQ / Saerens et al. 2002 is the EM point estimate of this model). It reuses from_posteriors with categorical bins.

The calibration assumption is doing all the work: a miscalibrated classifier gives miscalibrated prevalences. Worth a calibration check or a recalibration helper.

§8

Utilities

likelihoods.py · compress (l. 380), subset, with_weights, with_selection, to_sparse, stack (l. 403)
  • compress() merges identical (normalised) rows into one row whose weight is the sum, keeping total absolute log-likelihoods exact (the stored log-scale is the weighted mean). Huge savings for binned photometry, discrete measurements and unfolding.
  • subset / indexing keep bins, weights, selection and per-object metadata aligned.
  • to_sparse(rtol) drops entries below rtol × row maximum.
  • stack(interim_prior): the classic stacked estimate, one EM step from the interim prior (decision #11 will make it honour the stored interim prior and report its KKT gap).

Audit: I-5, I-6 (stack defaults and NaNs), I-7 (compress densifies sparse input: 27 s and 2.4 GB on 50k × 2000; keying sparse rows takes 0.06 s), I-19, I-21.
