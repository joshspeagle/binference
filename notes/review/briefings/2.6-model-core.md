# Briefing 2.6: The model object and its kernels (record)

Interactive page: `2.6-model-core.html`. Files: model.py, _kernels.py, _simplex.py.

- PopulationModel holds likelihoods, prior_spec/prior (default Dirichlet(1)), selection
  spec/values/mode/_detect, _L (effective; shared, not copied), _w, W, _ll_const.
  Methods: unconstrained (log_prob_and_grad …), value space (log_likelihood …),
  diagnostics (kkt_gap, missing_information). log_prob vs log_posterior naming (#15).
- One evaluation: prior.forward → softmax/exp → kernel two passes + selection/rates
  terms → prior.log_prior_and_grad (chain rule) → + _ll_const. −inf with zero gradient
  if any L_i·ρ ≤ 1e-250 (counts zero-weight rows: M-1). transform() loops in Python.
- Kernels: two passes; chunked responsibilities/labels; CSR labels via one global
  cumsum; Mult for integer weights. Benchmark (experiments/2.6_kernel_speed.py, single
  thread): 2e4×80 1.2 ms (22 GB/s); 2e5×100 26 ms (12 GB/s); 1e6×50 93 ms (9 GB/s);
  CSR at 58% non-zero slower than dense. float32 L mixed with float64 vectors 4–9×
  slower (silent conversion); consistent float32 ≈ float64 speed here, half memory.
  Memory-bound: fused single pass ~2×, cores, GPU post-v1.
- _simplex: cached frozen Helmert basis; stable softmax; clr needs ρ > 0.
- kkt_gap: M-3 false 0 at impossible points (Python max with NaN); M-4 rates units.
  missing_information: M-2 corrected formula; useful input to #14 routing.
- Audit M-1…M-14 listed (major: M-1 zero-weight rows in bootstrap EM).
- To decide: speed plan (fused kernel as optional compiled extra, multi-core, sparse
  threshold from benchmarks); float32 option; KKT fixes; "each concept implemented once".
