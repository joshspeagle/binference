Selection, in the code

The design was settled in 2.1 (#7–#10, #30). This page reads how the current code carries selection through the model and each engine, checks it, and lists where it falls short of those decisions. Files: selection.py (110 lines), model.py, samplers/base.py, gibbs.py, vb.py, optimize.py, results.py, simulate.py.

§1

The Selection object

selection.py · Selection, as_selection
  • A value object: per-bin values $S_k$ (strictly positive, finite) plus a mode, "observed" or "true" (to become on_measurement / on_truth, #7).
  • as_selection enforces the rule from D9: an array needs an explicit mode, a mode needs a selection, and they must agree with a Selection object.
  • Zero values are refused: a bin that can never be seen is not identifiable from the data, so the user is told to remove it.
  • It is reassignable after construction (mode, values), unlike Bins (audit: give it the same immutability guard).

§4

Why only ratios of S matter, and when they don't

Gibbs and EM impute the number of objects that were never seen, which seems to need absolute detection probabilities. The code uses $S/\max S$ instead. It is still exact for $\rho$, because the imputation follows from a $1/N$ prior on the total number of objects (the same scale-free prior as the rates derivation, #9). Summing over the unseen total:

$$\sum_{m\ge0}\frac{1}{W+m}\binom{W+m}{W}(1-p)^m\,p^W = \frac{1}{W}\quad\Rightarrow\quad p(\rho\mid D)\ \propto\ p(\rho)\,\frac{\prod_i \tilde L_i\cdot\rho}{(S\cdot\rho)^W},$$

where $p = S\cdot\rho$. Multiplying $S$ by $c$ multiplies the numerator by $c^W$ and the denominator by $c^W$, so the posterior for $\rho$ doesn't change. The same cancellation makes EM's fixed point scale-free, with or without a Dirichlet prior.

But the total does depend on the scale. The imputed number of missed objects, and the rates derived per draw under #9 ($\Lambda\sim\mathrm{Gamma}(N_{\rm obs}, S\cdot\rho)$), are only meaningful if $S$ is an absolute probability (or an exposure). Today a Selection doesn't say which it is, and the mocks silently clip values above 1 while the model uses their ratios (audit G-4: true ρ = (0.5, 0.5) fitted as (0.33, 0.67)). Proposal: Selection records whether its values are absolute (probabilities ≤ 1, or exposures) or relative; absolute totals and rates are refused for relative ones.
§5

New: selection has its own binning bias

$S_k$ must be the detection probability averaged over the objects in bin $k$: $S_k = \int_{B_k} S(z)\,p(z)\,dz \,/ \int_{B_k} p(z)\,dz$. That average depends on the population's shape inside the bin, which is unknown. Users who average $S(z)$ flat over the bin make the flat-within-bin assumption a second time. With a steep completeness edge inside a bin, the error goes straight into $\rho_k$ (for on-truth selection with precise data, $\hat\rho_k \propto n_k/S_k$), and it does not shrink with N.

Flat-averaged vs true Sk

bias in ρk from a flat-averaged Sk±1 statistical s.d.

Ten bins on [0, 1]; population ∝ e−z/scale; completeness a logistic edge. Bias = Sktrue/Skflat − 1 (large N, precise data, on-truth selection); statistical s.d. ≈ 1/√(N ρk Sk / Σρ S).

Defaults (edge 0.2 bin widths wide, inside bin 6, population falling with scale 0.2): bin 6's fraction is off by 11%, which equals its statistical error at N ≈ 6,600 objects. A sharper edge (0.1 bins) gives 15% and N ≈ 3,500; an edge one bin wide still gives 2.3% (N ≈ 120,000); a flatter population (scale 1) shrinks it to 2.2% (N ≈ 45,000). Bins far below the edge have large relative errors too, but too few detections for them to matter.

The fix is already decided: a callable $S(z)$ (#10) evaluated at the internal resolution or basis (#4, #5), the same remedy as for the likelihoods. It also belongs in the binning-bias diagnostic (#6).
