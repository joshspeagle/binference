Docs content plan

Step 2 of the docs phase (issue #99). It rests on three audits of the current site: accuracy against the code, structure and writing, and visuals and tooling. Read it alongside the logo round. Your answers to section 8 and your logo choice are the two gates before the build starts.

1 · What the audit found

36wrong or stale statements

Each one was reproduced against the code. Five examples publish fits that did not converge.

3code bugs

An explicit MAP algorithm could silently run L-BFGS, and the ESS message rounded the per-chain value up to the limit. Fixed in PR #101.

11equal menu entries

One flat list of pages, including internal ones. There is no glossary and no layer of concepts between the pitch and the maths.

3–7copies of one fact

About ten facts each live in several places, and one copy has already drifted.

26figures

All are notebook PNGs, with file paths as alt text and text 4–9 px high on a phone. Nothing outside the tutorials has a figure.

8names for one quantity

fractions, proportions, prevalence, n(z), g … Also S, λ, ℓ and w each carry two to four meanings.

What works: the tutorials (executed, short, and they show failure modes), the field background pages, accessibility (axe finds no violations), and pages that never scroll sideways. The wrong statements are being fixed on the current site now (issue #102), so the live site is right while the redesign is built.

2 · Readers and writing rules

Readers, in order: students and non-experts with data in hand; practitioners in any field; expert statisticians. Astronomy leads the examples, and every input type and field has its own way in.

Writing rules (a new contribute/writing page, after dorothy's)

  • Sentences of at most 25 words, instructions of at most 20, one idea per sentence. Active voice, and a condition before its instruction.
  • One word per meaning, from the glossary. Field names (n(z), prevalence, mixing distribution) appear only on that field's pages, as synonyms.
  • One symbol per meaning, from a notation page: the selection keeps S, the rates keep λ, and the other uses of each are renamed.
  • Each fact has one home, and other pages link to it. Defaults and constants live in Reference, not in the theory.
  • Measured figures only, with their setup. Every number on a page comes from code that CI runs.
  • No DECISIONS #n in user pages or docstrings (107 today). The reason for a design belongs in its issue or PR.
  • Each concept page opens with the question it answers and asks the reader to run no code.

6 · Tooling

  • Theme: a local Sphinx theme that inherits basic, as dorothy's does. It adds everything PyData gives today: notebook output styles, numpydoc and API styling, a grouped API sidebar, scrolling for wide tables and maths, search, the phone menu, and a dark mode that tutorial plots follow.
  • Home page: a template, so sphinx-design (used only for the eight home cards) can go.
  • Citations: sphinxcontrib-bibtex with dorothy's author-year style; one references.bib replaces about 94 hand-written references.
  • Checks:
    • a test that every __all__ name appears once in the API pages (8 are missing today);
    • a weekly link check;
    • the snippet runner also on the home page;
    • MathJax pinned;
    • intersphinx either linked properly or dropped (it fetches four inventories and links nothing).
  • Explainer maths: where an explainer reproduces a binference computation, a test compares the two.
  • Final pass: every page at 390 and 1440 px in both themes, with no sideways scroll, no console errors and AA contrast; axe again.

7 · Order of work

  1. Now: code bugs (PR #101) and accuracy fixes on the current site (#102).
  2. Your gates: pick a logo direction and answer section 8. Then round 2 produces the full design sheet, which you lock.
  3. Design document: docs/design/brand.md with the logo files and the script that draws them.
  4. Theme with the text unchanged: theme, home template, citations, plot style, API coverage test.
  5. Structure with the text unchanged: every page moved to its final place, captioned menus, design notes out of the menu.
  6. Section rewrites, in parallel, each in its own worktree and PR: Start and README; Concepts with V-1 to V-7, V-10 and V-13; Tutorials regrouped, plus the samples tutorial; Guides; How it works; Reference; Fields.
  7. Explainers and the home hero that the rewrites did not need.
  8. Final pass and a phase report on #99. Then the 3.1 review page is updated and the walkthrough resumes.

8 · Your calls

Each has a default that I will follow unless you say otherwise.

1. One name for the quantity being inferred

Default: population fractions (ρ), with rates (λ) for expected numbers. Field names (n(z), prevalence, mixing distribution) appear as synonyms on field pages only.

2. Seven top-bar sections (Start, Concepts, Tutorials, Guides, How it works, Fields, Reference)

Default: as listed. The alternative folds Concepts into Start, leaving six.

3. A new tutorial built on posterior samples

Default: yes. It reworks the gravitational-wave tutorial to start from PE samples and their PE prior, so every input type has an end-to-end path.

4. Old addresses

Default: no redirects, since nothing has been released. Pages move freely.

5. Tutorial plots

Default: matplotlib with a shared style and transparent backgrounds, so they sit in both themes. The alternative, SVG redrawn in theme colours, costs a second plotting path.

6. Classifier routes

Default: rename routes "A" and "C" for what the user has, e.g. "posteriors and the training prevalence" and "scores and a labelled set". This changes the guide and tutorial text only, not the API.
