# Astronomy density deconvolution and hierarchical histogram tools (outside photo-z and GW): census for pastry

Status: complete (2026-10-22). Key questions are answered in the order given in the brief (Q1-Q5); a one-table census of every verified tool is in Q4.

Conventions used below. "Verified" means I read the repository (shallow clone of the default branch, read via `git show`, nothing executed) and/or its package-index page on 2026-10-22. Stars and push dates come from the GitHub search API on 2026-10-22. "Last commit" is the date of the newest commit on the default branch in the clone. I did not run any of these codes.

## Q1. Gaia and stellar-population examples (Leistedt & Hogg 2017; Anderson et al. 2018; CMD flows; Hess-diagram/SFH codes)

### Takeaway
Leistedt & Hogg (2017) is, almost exactly, pastry's baseline model (fixed kernels/bins on the CMD, Dirichlet prior on amplitudes, precomputed per-star bin likelihoods, Gibbs sampling over 1.4 million stars) but its code (Starlight) is an unmaintained 2017 research repo; Anderson et al. (2018) used the XD/empirical-Bayes alternative and explicitly flag its double use of data and Gaussian-noise restriction; flow-based CMD/phase-space deconvolution (Cranmer et al. 2019; Yan & Sanders 2025) gives point-estimate densities with no population uncertainty (the "Bayesian" in Cranmer et al.'s title refers to the per-star distance posteriors, not to the flow). The best-engineered reusable "bin weights from counts with uncertainties" code in this area is StarFormationHistories.jl (Julia, Poisson likelihood ratio, MLE/MAP/HMC/MCMC, v2.0.0 on 2026-10-11); MATCH, the community standard, has no public repository I could find.

### Cited Findings
- Leistedt & Hogg 2017 (AJ 154, 222; doi:10.3847/1538-3881/aa91d5; arXiv:1703.08112, "Hierarchical probabilistic inference of the color-magnitude diagram and shrinkage of stellar distance uncertainties") — [arXiv:1703.08112](https://arxiv.org/abs/1703.08112)
- Model: CMD modelled as a mixture of B fixed Gaussian kernels with amplitudes {f_b} summing to one; inference by Gibbs sampling alternating Dirichlet draws of {f_b} given bin counts {n_b} and per-star multinomial draws of bin b_s with probability ∝ f_b g_bs, where g_bs (distance-marginalised likelihood of star s in kernel b) is precomputed once because kernels are fixed; "the bins can be simply drawn from a multinomial distribution"; applied to the 1.4 million Gaia TGAS+APASS stars; "Our hierarchical model has 4 million parameters in total, most of which are marginalized out"; kernels tile colour and magnitude "with 60 points" each; 10,000 Gibbs samples — [paper source in GitHub ixkael/Starlight, paper/shrinkingparallaxes.tex](https://github.com/ixkael/Starlight)
- Same paper: "we did not add the recommended parallax error offset of 0.3 because overestimated errors typically cause excessive deconvolution"; selection effects ignored ("could be incorporated but require external data and modifications to the sampling method"); uniform distance priors — [shrinkingparallaxes.tex](https://github.com/ixkael/Starlight)
- Code: `ixkael/Starlight` ("Data-driven, hierarchical models of Milky Way stars"), Python/Cython, MIT, `SimpleHRDModel.gibbs_sampler`, HMC module, pytest tests, Travis/coveralls badges; last commit 2017-11-07; 0 stars — [GitHub ixkael/Starlight](https://github.com/ixkael/Starlight)
- Anderson, Hogg, Leistedt, Price-Whelan & Bovy 2018 (AJ, doi:10.3847/1538-3881/aad7bf; arXiv:1706.05055): XD (via xdgmm) on 2MASS colours + TGAS parallaxes for 1.4 million stars, K = 128 Gaussians fixed "(with only heuristic analysis)"; XD described as "an Empirical Bayes approximation to a full hierarchical model"; "its use as a prior is technically using the data twice and is therefore only approximately valid"; XD "requires or implies a strictly Gaussian noise model", forcing a transform of the CMD to a space where noise is approximately Gaussian — [paper source in GitHub andersdot/photoParallax, paper/paper.tex](https://github.com/andersdot/photoParallax)
- Code: `andersdot/photoParallax` scripts (uses `from xdgmm import XDGMM`), "All rights reserved" (no open licence), last commit 2018-07-30, 2 stars — [GitHub andersdot/photoParallax](https://github.com/andersdot/photoParallax)
- Anderson et al.: "With large data sets, the MMLE or Empirical Bayes approximation is safe, in some sense, because no individual data point makes a large difference"; the fully correct alternatives are leave-one-out or full hierarchical inference "in which we treat the CMD parameters probabilistically" — [paper.tex](https://github.com/andersdot/photoParallax/blob/master/paper/paper.tex)

#### Flow-based CMD and phase-space deconvolution (astronomy applications; brief)
- Cranmer, Galvez, Anderson, Spergel & Ho 2019 (arXiv:1908.08045): MADE-based normalizing flow for the dereddened Gaia DR2 CMD trained on 640M stars, producing distance posteriors; noise handled approximately — 32 truncated-normal parallax samples per star are combined into a "best-estimate" CMD point with combined uncertainty σ_P, and the loss is a σ_P^-2-weighted negative log density, not a convolved likelihood; architecture chosen from 80 models by Bayesian optimisation; uses PyTorch code adapted from ikostrikov/pytorch-flows — [arXiv:1908.08045](https://arxiv.org/abs/1908.08045)
- The promised code repository `MilesCranmer/public_CMD_normalizing_flow` contains only a README (1 file, last commit 2020-01-08) ("This repository will host code, and links to data"); the companion `xd_vs_flow` demo (FFJORD continuous flow with added noise treatment vs XD, needs torchdiffeq, extreme-deconvolution and XDGMM) has no licence, last commit 2020-01-08 — [GitHub public_CMD_normalizing_flow](https://github.com/MilesCranmer/public_CMD_normalizing_flow); [GitHub xd_vs_flow](https://github.com/MilesCranmer/xd_vs_flow)
- Yan & Sanders 2025 (arXiv:2505.16553; MNRAS-format preprint): flow density deconvolution for Gaia velocity space with heteroscedastic noise; "The denoising is performed using importance sampling" (Monte Carlo estimate of p(w_i) by sampling v from the per-star noise distribution), compared against XD; recommends two-stage training — a cheap pre-training loop ignoring uncertainties, then fine-tuning with the importance-sampled likelihood; built on Zuko + PyTorch — [arXiv:2505.16553](https://arxiv.org/abs/2505.16553)
- Code `Ziyang-Yan/Denoising-Milky-Way-with-NF`: MIT, module `dmw_nf` (flow.py, utils.py, plotting.py), trained models included, last commit 2026-02-27, no packaging or tests — [GitHub Ziyang-Yan/Denoising-Milky-Way-with-NF](https://github.com/Ziyang-Yan/Denoising-Milky-Way-with-NF)
- Kang, Hennawi, Schindler, Tamanas & Nanni 2024 (arXiv:2412.03029, "Extreme Deconvolution Reimagined"): CondXD — XD generalised to conditional densities, with GMM parameters output by a neural network of non-Gaussian conditioning features; motivates that "XD does not generalize to cases where some feature dimensions have highly non-Gaussian distribution" — [arXiv:2412.03029](https://arxiv.org/abs/2412.03029); code [GitHub enigma-igm/CondXD](https://github.com/enigma-igm/CondXD)
- arXiv API search (2026-10-22) for Gaia + deconvolution + colour-magnitude/Hertzsprung found no newer hierarchical CMD-deconvolution paper beyond these — [arXiv API query](https://export.arxiv.org/api/query?search_query=abs:deconvolution+AND+abs:Gaia)

#### StarFormationHistories.jl (Garling et al. 2025) — Hess-diagram template weights
- "implements methods for modelling observed Hess diagrams (which are just binned color-magnitude diagrams...) and using them to fit astrophysical star formation histories"; registered in Julia's General registry (`Pkg.add("StarFormationHistories")`); paper arXiv:2407.19534, ApJS doi:10.3847/1538-4365/adbb64; software DOI 10.5281/zenodo.14963317 — [GitHub cgarling/StarFormationHistories.jl](https://github.com/cgarling/StarFormationHistories.jl)
- MIT; v2.0.0 released 2026-10-11 (CHANGELOG); pushed 2026-10-18; 6 stars, 9 open issues; GitHub Actions CI, codecov, Aqua.jl QA, benchmarks, Documenter docs (stable/dev) — [CHANGELOG.md](https://github.com/cgarling/StarFormationHistories.jl/blob/main/CHANGELOG.md); [docs](https://cgarling.github.io/StarFormationHistories.jl/stable/)
- Model: observed Hess diagram n_i ~ Poisson(m_i), m_i = Σ_j r_j c_ij (templates c_ij per unit stellar mass, including photometric error, completeness and binaries via "blurred isochrone" kernels derived from artificial-star tests); objective is the Poisson likelihood ratio of Dolphin (2002), −ln L = Σ_i m_i − n_i(1 − ln(n_i/m_i)) — [docs: fitting intro / unconstrained fitting](https://cgarling.github.io/StarFormationHistories.jl/stable/)
- Inference options: `fit_templates_lbfgsb` (bounded L-BFGS-B MLE; "It provides no uncertainty estimation. It is normal for some of the coefficients to converge to zero"); `fit_templates_fast`; `fit_templates` (recommended: BFGS MAP in θ_j = ln r_j with Jacobian, giving an inverse-Hessian covariance); `mcmc_sample` (KissMCMC, emcee-style stretch move); `hmc_sample` (DynamicHMC on log coefficients); hierarchical age–metallicity and mass–metallicity relation models — [docs: unconstrained fitting](https://github.com/cgarling/StarFormationHistories.jl/blob/main/docs/src/fitting/unconstrained.md)
- Empirical posterior shape: "the sampled r_j for coefficients that are non-zero in the MLE are approximately Gaussian distributed while the logarithms of the sampled r_j are roughly Gaussian distributed for coefficients that are zero in the MLE" — [docs](https://github.com/cgarling/StarFormationHistories.jl/blob/main/docs/src/fitting/unconstrained.md)
- v2.0.0 additions relevant to pastry: `cum_sfr_quantiles` computes quantiles of per-sample totals "which account for the correlations between time bins, unlike sums of the per-bin star formation rate quantiles"; fitted background templates because "Contaminants such as background galaxies and foreground stars otherwise bias the fit toward more old stars and broader metallicity dispersions"; `hess_mask` to exclude bins; adaptive importance sampling across modes for single-population fits; LogDensityProblems.jl interface "for use with other samplers"; a fix where clamping the model at eps made "the gradient inconsistent with the objective" (now adds eps instead) — [CHANGELOG.md](https://github.com/cgarling/StarFormationHistories.jl/blob/main/CHANGELOG.md)

#### MATCH (Dolphin 2002) and other Hess-diagram codes
- MATCH is described in the literature as a maximum-likelihood CMD-fitting package using a Poisson likelihood statistic over synthetic SSP CMDs (IMF, binary fraction, fixed age/metallicity/colour/magnitude bins); I found no public repository, download page or licence — [web search results incl. arXiv:1201.4859, arXiv:1405.3281](https://arxiv.org/pdf/1201.4859)
- PANCAKE (Zheng et al. 2025, arXiv:2505.04534): Python CMD-fitting package (template generation, uniform/quadtree/Voronoi gridding, fitting); notes star counts per bin are Poisson but fits the template weight matrix with a Mean Squared Error loss using PyTorch Adam (lr 0.001, 50,000 epochs) and clips negative weights to zero each epoch; random uncertainties via bootstrap Monte Carlo or MCMC mentioned; isochrone systematics can be "2-4 times larger than the random uncertainties" (citing Dolphin 2012) — [arXiv:2505.04534](https://arxiv.org/abs/2505.04534)
- PANCAKE code: `Yunzheng168/PANCAKE`, MIT, script-driven (`python run_Pancake.py -c ini_para`), ~1,580 files including bundled isochrones and committed `__pycache__`, last commit 2025-04-22, not packaged — [GitHub Yunzheng168/PANCAKE](https://github.com/Yunzheng168/PANCAKE)

#### BEAST / MegaBEAST (resolved-star SEDs → ensemble parameters)
- MegaBEAST: "hierarchical Bayesian model for ensembles of dust extinguished stellar populations" that uses the BEAST per-star n-dimensional posteriors and includes completeness from artificial-star tests; README: "In Development!"; BSD-3; last commit 2024-07-30; not on PyPI — [GitHub BEAST-Fitting/megabeast](https://github.com/BEAST-Fitting/megabeast); [PyPI lookup](https://pypi.org/project/megabeast/)
- MegaBEAST likelihood (source): per star, Σ over its stored sparse BEAST grid points of (likelihood × population model weight × BEAST prior weight × grid weight × completeness), log-summed, plus a Poisson term for the observed number of stars given the predicted number ("equation 8 in Weisz et al. (2013, ApJ, 762, 123)"); sampled with emcee — [megabeast/singlepop_dust_model.py](https://github.com/BEAST-Fitting/megabeast/blob/master/megabeast/singlepop_dust_model.py)
- BEAST (per-star fitter feeding MegaBEAST): PyPI `beast` 2.1.0 (2025-05-16), BSD-3, last commit 2026-09-15 — [PyPI beast](https://pypi.org/project/beast/); [GitHub BEAST-Fitting/beast](https://github.com/BEAST-Fitting/beast)

### Inferences
- pastry's baseline is not novel in astronomy: Leistedt & Hogg's Gibbs sampler (Dirichlet given counts; categorical given ρ with precomputed per-object kernel likelihoods g_bs) is exactly the Dirichlet–multinomial with known L_ik. What is missing is a maintained, general, documented package — Starlight was never released as one. pastry can cite it as prior art and reproduce its TGAS demo as a benchmark.
- The "precompute per-object likelihood over fixed kernels" trick is what makes 10^6 objects tractable; pastry should store L as an (N, K) array (dense or sparse/top-k like BEAST's lnp files) and never re-evaluate likelihoods inside the sampler.
- StarFormationHistories.jl shows the binned-counts (Poisson, response-matrix) side of the same problem: when per-object information is only "which Hess bin", the model becomes counts n ~ Poisson(C r) with a template/response matrix C. pastry could accept a response matrix plus counts as an alternative input, and should copy (a) log-coefficient HMC with Jacobian, (b) Laplace/inverse-Hessian quick errors, (c) per-sample derived quantities to keep inter-bin correlations, (d) explicit background/contaminant components.
- MegaBEAST is the closest astronomy analogue of pastry's "posterior grids under an interim prior" input: it multiplies stored per-star likelihood × prior-weight grids by a population model and completeness. Its unfinished state suggests the reusable core (sparse per-object grids, completeness, expected-count Poisson term) is in demand but unserved.
- MSE-on-histograms fitting (PANCAKE) is a counter-example to cite: it ignores Poisson heteroscedasticity and yields no principled uncertainty.

### Gaps
- I could not verify MATCH's licence or distribution channel (no public repository found); StarFISH (Harris & Zaritsky 2001) and other legacy Hess-diagram codes were not checked.
- I did not find a 2022-2026 flow-based or hierarchical deconvolution of the Gaia DR3 CMD with released code; arXiv searches returned only the 2017-2019 works plus velocity-space flows.
- The number of CMD kernels in Leistedt & Hogg (60 points per axis, i.e. presumably 3,600 kernels) is my reading of the paper source, not an explicitly quoted total.

## Q2. The extreme-deconvolution (XD) family: inputs, truncation/selection, uncertainty on the deconvolved density, maintenance

### Takeaway
Every XD implementation assumes Gaussian per-object noise (mean + covariance, optionally with a projection matrix) and returns a maximum-marginal-likelihood Gaussian mixture with no posterior uncertainty on the deconvolved density (only a 2010 IDL jackknife add-on for the reference code, and BIC/AIC scans for the number of components in xdgmm). Truncation/selection is handled only by pygmmis (known completeness callback, EM with imputation; pure Python, last release 2022) and, since September 2026, by the JAX beta package deconvgmm (known selection via its convMMD estimator, labelled "Pending"). The reference C code (Bovy) is maintained (CI on Python 3.9-3.14, July 2026) but not pip-installable; astroML's XDGMM is pure Python with R = I only; the GPU/minibatch (Ritchie & Murray 2019) and flow (Dockhorn et al. 2020) PyTorch codes are unreleased (not on PyPI), unlicensed paper code; gmmx (JAX) is a fast plain GMM without deconvolution.

### Cited Findings

#### extreme-deconvolution (Bovy, Hogg & Roweis), reference implementation
- What: C library (GSL, OpenMP) with Python (ctypes), IDL and R wrappers; "infer a d-dimensional distribution function from a set of heterogeneous, noisy observations or samples"; claims it works "from small data sets with only tens of samples per dimension, to large data sets with millions of data points" — [GitHub jobovy/extreme-deconvolution README](https://github.com/jobovy/extreme-deconvolution)
- Paper: Bovy, Hogg & Roweis 2011, Ann. Appl. Stat. 5, 2B, 1657, arXiv:0905.2979 — [README "Acknowledging"](https://github.com/jobovy/extreme-deconvolution)
- Licence BSD-3-clause (LICENSE copyright 2008-2014 Bovy, Hogg, Roweis; GitHub reports NOASSERTION) — [LICENSE](https://github.com/jobovy/extreme-deconvolution/blob/main/LICENSE)
- Maintenance: last commit 2026-07-20 (a dependabot bump of CI actions); 85 stars, 23 forks, 1 open issue (GitHub API 2026-10-22); setup.py version 1.3 (v1.3 dates from 2011-06-12 per README News); README says the tagged release is out of date and to install from `main` — [repo](https://github.com/jobovy/extreme-deconvolution)
- Not on PyPI (PyPI JSON API returns 404 for `extreme-deconvolution`); installation is `make; sudo make install; make pywrapper` then add `py/` to PYTHONPATH; needs GSL — [README Installation](https://github.com/jobovy/extreme-deconvolution); [PyPI lookup](https://pypi.org/project/extreme-deconvolution/)
- Testing: GitHub Actions matrix Python 3.9-3.14, pytest tests (test_oned, test_twod, test_fix, test_log) plus C coverage via lcov/codecov; weekly scheduled build — [.github/workflows/build.yml](https://github.com/jobovy/extreme-deconvolution/blob/main/.github/workflows/build.yml)
- Inputs: `ydata [ndata,dy]`, `ycovar [ndata,dy(,dy)]` (diagonal or full Gaussian error covariances), optional per-object `projection [ndata,dy,dx]` matrices (so data can live in a different/lower-dimensional space than the model), optional per-object `weight`/`logweight`; fix flags for amplitudes/means/covariances; `w` covariance regulariser ("of the conjugate prior"); split-and-merge depth; `likeonly` to only evaluate the likelihood — [py/extreme_deconvolution.py docstring](https://github.com/jobovy/extreme-deconvolution/blob/main/py/extreme_deconvolution.py)
- API (in-place update of initial guesses): `from extreme_deconvolution import extreme_deconvolution; extreme_deconvolution(ydata, ycovar, initamp, initmean, initcovar)` ("initamp, initmean, and initcovar are now updated to their best fit values"); returns average log-likelihood — [README Usage](https://github.com/jobovy/extreme-deconvolution)
- Missing data handled by giving unobserved dimensions very large errors; the README warns the split-and-merge hierarchy is not correct if projection matrices are not full rank — [README](https://github.com/jobovy/extreme-deconvolution)
- Uncertainty: the core code returns only the MLE; IDL "addons" (2010) include `exd_jackerr.pro` ("calculate uncertainties on the best-fit parameters" by jackknife), membership probabilities, and a weighted KS test — [README News 2010/06/11; addons/](https://github.com/jobovy/extreme-deconvolution/tree/main/addons)
- Known issue: "For small data sets the algorithm will very rarely decrease the likelihood in a step" (numerical instability) — [README Outstanding issues](https://github.com/jobovy/extreme-deconvolution)

#### astroML `XDGMM` (pure-Python XD)
- `astroML.density_estimation.XDGMM(n_components, max_iter=100, tol=1e-5)`; `fit(X, Xerr, R=None)` where `Xerr` must be full covariances `(n_samples, n_features, n_features)`; `R` (projection) "is not yet implemented" and raises NotImplementedError; methods `logprob_a`, `logL`, `sample`; subclass of sklearn `BaseEstimator` — [astroML/density_estimation/xdeconv.py](https://github.com/astroML/astroML/blob/main/astroML/density_estimation/xdeconv.py)
- astroML: BSD licence (setup.cfg says 3-clause; GitHub detects BSD-2-Clause); latest PyPI release 1.0.2.post1 uploaded 2022-03-01 (13 releases since 2013); last commit on main 2024-01-04; 1,206 stars, 71 open issues; GitHub Actions CI badge — [PyPI astroML](https://pypi.org/project/astroML/); [GitHub astroML/astroML](https://github.com/astroML/astroML)
- astroML also ships `bayesian_blocks`, `histtools` (bin-width rules) and `gauss_mixture` alongside `xdeconv` — [astroML density_estimation tree](https://github.com/astroML/astroML/tree/main/astroML/density_estimation)

#### xdgmm (Holoien, Marshall & Wechsler 2017)
- scikit-learn-compatible wrapper exposing both the astroML and the Bovy fitters (`method='astroML'|'Bovy'`), with `score_samples`, `predict`, `predict_proba`, `bic`, `aic`, `bic_test/aic_test` over a range of K, `sample`, `condition` (conditional GMM given known values of some dimensions), `save_model/read_model` — [xdgmm/xdgmm.py](https://github.com/tholoien/XDGMM/blob/master/xdgmm/xdgmm.py); [README](https://github.com/tholoien/XDGMM)
- MIT licence; setup.py version 1.0.9; depends on astroML and scikit-learn; Travis CI badge (travis-ci.org) rather than GitHub Actions; last commit 2023-07-10 (a port PR); 26 stars; not on PyPI (404) — [GitHub tholoien/XDGMM](https://github.com/tholoien/XDGMM); [PyPI lookup](https://pypi.org/project/xdgmm/)
- Paper: Holoien, Marshall & Wechsler 2017 (AJ, doi:10.3847/1538-3881/aa68a1; arXiv:1611.00363, "EmpiriciSN"), conditional XD for supernova host properties — [README citation](https://github.com/tholoien/XDGMM)

#### pygmmis (Melchior & Goulding 2018)
- Pure-Python GMM "for incomplete (missing or truncated) and noisy data": XD-style per-sample Gaussian errors; missing features via huge variances; truncated data / variable completeness "as long as you know the incompleteness over the entire feature space, and the incompleteness does not depend on the sample density (missing at random)"; optional uniform background component; neighbourhood tracking for speed; EM that "generates its best guess of the unobserved samples on the fly"; parallelised with multiprocessing; "capable of performing density estimation with millions of samples and thousands of model components" — [README](https://github.com/pmelchior/pygmmis)
- API: `gmm = pygmmis.GMM(K=K, D=D); logL, U = pygmmis.fit(gmm, data, init_method='random', sel_callback=cb, covar_callback=covar_cb, w=w, cutoff=cutoff, background=bg, tol=tol, frozen=frozen, rng=rng)`; `pygmmis.draw(gmm, obs_size, sel_callback=cb, ...)` returns samples plus `N_orig`, "the estimated number of samples prior to selection"; a `covar_callback` is required when errors are heteroscedastic and selection is non-trivial (errors must be predicted at unobserved locations) — [README "How to run the code"](https://github.com/pmelchior/pygmmis)
- MIT; PyPI 1.2.3 uploaded 2022-07-21 (10 releases since 2018); last commit 2022-07-20; 105 stars, 4 open issues; "developed and tested in 2.7"; tests are two scripts (`tests/test.py`, `tests/test_3D.py`) rather than a unit-test suite — [PyPI pygmmis](https://pypi.org/project/pygmmis/); [GitHub pmelchior/pygmmis](https://github.com/pmelchior/pygmmis)
- Paper: Melchior & Goulding 2018, "Filling the gaps: Gaussian mixture models from noisy, truncated or incomplete samples", Astronomy and Computing, doi:10.1016/j.ascom.2018.09.013, arXiv:1611.05806 — [README badges](https://github.com/pmelchior/pygmmis)

#### Scalable XD (Ritchie & Murray 2019) and NF deconvolution (Dockhorn, Ritchie, Yu & Murray 2020)
- Ritchie & Murray (arXiv:1911.11663): two minibatch XD variants (online EM and direct SGD on the log-likelihood) in PyTorch that "can run on GPUs"; tested on 2 million Gaia rows; K = 256 fitted with minibatch EM; "GPU-based computation speeds up fitting considerably, allowing sublinear scaling of training time" — [arXiv:1911.11663](https://arxiv.org/abs/1911.11663)
- Code `bayesiains/scalable_xd`: package `deconv` v1.0 (setup.py), single "Initial code copy" commit 2019-10-30, no licence file, 4 stars; README: "At some point in the future we hope to tidy it up and refactor it into a proper package" — [GitHub bayesiains/scalable_xd](https://github.com/bayesiains/scalable_xd)
- Dockhorn et al. (arXiv:2006.09396): flows for the deconvolved density with arbitrary noise, trained by amortised VI (ELBO and importance-weighted IWAE bound); "flows can already out-perform Gaussian mixtures for density deconvolution" on real data but "we demonstrate some problems involved in this approach" — [arXiv:2006.09396](https://arxiv.org/abs/2006.09396)
- Code `bayesiains/density-deconvolution`: last commit 2020-06-10, no licence, 12 stars; requires the authors' fork of `nflows` — [GitHub bayesiains/density-deconvolution](https://github.com/bayesiains/density-deconvolution)
- Name collision: the PyPI package `deconv` (0.9.5, 2026-02-23) is an unrelated biology package (lutrarutra/deconv), not the bayesiains code — [PyPI deconv](https://pypi.org/project/deconv/)

#### Other GMM/XD codes found
- gmmx (Axel Donath): "A minimal implementation of Gaussian Mixture Models in Jax" with `EMFitter`; plain GMM (no per-object noise deconvolution in the README); BSD-3; PyPI 0.7 (2025-07-07); last commit 2026-08-07; 26 stars; codecov + CI; README reports ~5-6x CPU and ~50x GPU speed-ups over scikit-learn — [GitHub adonath/gmmx](https://github.com/adonath/gmmx); [PyPI gmmx](https://pypi.org/project/gmmx/)
- CondXD (enigma-igm): conditional XD where GMM parameters are neural-network functions of a conditioning variable (PyTorch), used for quasar/contaminant densities; setup.py 1.0, BSD classifier but no licence file; last commit 2025-06-29; 2 stars; README only "see CondXD/example.py" — [GitHub enigma-igm/CondXD](https://github.com/enigma-igm/CondXD)
- deconvgmm (Ritwik Vashistha, 2026): "Gaussian-mixture density deconvolution in JAX — two ways": exact XD EM for x_i = z_i + ε_i, ε_i ~ N(0, S_i) with full covariances, and convMMD, "a likelihood-free / simulation-based objective that matches the noise-convolved model to the data via a convolutional Maximum Mean Discrepancy", with missing-at-random masks and (v0.3.0b1, 2026-09-10) "a known selection function (MNAR)" via an analytic Gaussian-window path or self-normalised importance sampling with ESS diagnostics; empirical-Bayes denoiser; jit/vmap/grad-able; tested against a NumPy reference on CPU only; "pre-1.0 beta", "every capability is Pending", "no performance claim"; GitHub-only install (`pip install "git+https://github.com/ritwikvashistha/deconvgmm.git@v0.3.0b1"`), not on PyPI; MIT; XD code "adapted from astroML"; 0 stars, created 2026-08-30 — [GitHub ritwikvashistha/deconvgmm README/CHANGELOG](https://github.com/ritwikvashistha/deconvgmm); [PyPI lookup](https://pypi.org/project/deconvgmm/)
- deconvgmm API (README quickstart): `from deconvgmm import Params, identity; noise = identity.fit_isotropic_noise([...], dimension=1); fit = identity.fit_converged(params, observations, noise); denoised = identity.posterior_mean(fit.parameters, observations, noise)`; method paper Vashistha, Sarkar & Farahi 2026 (arXiv:2606.21907, stat.ME), which proves convergence rates for convMMD sieve estimators with GMM or flow generators — [README](https://github.com/ritwikvashistha/deconvgmm); [arXiv:2606.21907](https://arxiv.org/abs/2606.21907)
- GitHub search for "extreme deconvolution" (2026-10-22, 58 hits) otherwise returns mostly forks, course material and paper scripts (e.g. xnicer, PNICER, xd4gws, gaia-xd) — [GitHub search](https://github.com/search?q=%22extreme+deconvolution%22&type=repositories)

### Inferences
- XD is the "Gaussian errors, free-form GMM density, point estimate" corner of pastry's problem space and the baseline pastry should benchmark against (optionally wrap). pastry's differentiators would be arbitrary per-object likelihoods (non-Gaussian, multimodal, gridded or sampled), posterior uncertainty on population quantities, explicit selection handling, and a maintained pip-installable package.
- pastry's fixed-bin/fixed-kernel model is the "fixed means and covariances, free amplitudes" limit of XD (the reference code already exposes `fixmean`/`fixcovar` flags); Leistedt & Hogg show that freezing the kernels turns XD's EM into a conjugate Dirichlet–multinomial Gibbs sampler. The amplitude-only EM is the classic mixture-proportion EM, useful in pastry for fast MAP/MLE initialisation before sampling.
- pygmmis's imputation approach to selection requires predicting the noise at unobserved locations; pastry can avoid this by working with per-bin (or per-object-per-bin) detection probabilities in a Poisson/normalised likelihood (see Q3).
- New JAX implementations (deconvgmm, gmmx) suggest JAX is becoming the accelerator backend of choice for this family; pastry should keep any GPU backend optional, given the dependency weight.

### Gaps
- I found no maintained, packaged PyTorch XD; `scalable_xd` and `density-deconvolution` remain 2019-2020 research code. deconvgmm is a beta whose convMMD capabilities are explicitly "Pending" with "no performance claim".
- I did not run any XD implementation (speed and correctness claims are the authors').
- The pygmmis paper's quantitative tests of its selection treatment were not reviewed; xnicer/PNICER (XD-based extinction tools) and tcup turned up in searches but were not assessed.

## Q3. Occurrence rates and population histograms with selection effects; Poisson-process likelihoods

### Takeaway
The exoplanet occurrence-rate literature already contains pastry's full "selection + interim prior + smoothness" model in paper form: Foreman-Mackey, Hogg & Morton (2014) combine an inhomogeneous Poisson-process likelihood with a completeness function, importance-sampled per-object posterior samples divided by the interim prior, a piecewise-constant (histogram) rate density and a Gaussian-process smoothness prior with marginalised hyperparameters, sampled by elliptical slice sampling. None of the occurrence-rate codes (exopop 2014, DR25-occurrence-public 2020, EPOS 2020, SysSim/ABC in Julia, Blunt et al. 2026 scripts) is a maintained general-purpose library; they are explicitly paper code. On the luminosity/mass-function side, dftools (R) is the most general maintained-ish tool (arbitrary per-object PDFs, effective-volume selection, MML with Hessian/bootstrap errors) but its last commit is 2021.

### Cited Findings

#### Foreman-Mackey, Hogg & Morton 2014 (ApJ 795, 64; arXiv:1406.3020) and `dfm/exopop`
- Model: catalogue treated as a draw from an inhomogeneous Poisson process with observable rate Q_c(w) Γ_θ(w) (completeness × occurrence rate density); rate density modelled "as a piecewise constant step function" with log step heights as parameters — [ms.tex in GitHub dfm/exopop](https://github.com/dfm/exopop/blob/main/document/ms.tex); [arXiv:1406.3020](https://arxiv.org/abs/1406.3020)
- Interim-prior correction: catalogue posteriors p(w_k | x_k, α) were "produced under a specific choice of a---probably 'uninformative'---interim prior"; the marginal likelihood is approximated by importance sampling, "money equation": p({x}|θ)/p({x}|α) ≈ exp(−∫ Γ̂_θ(w) dw) Π_k (1/N_k) Σ_n Γ̂_θ(w_k^(n)) / p(w_k^(n) | α) — [ms.tex](https://github.com/dfm/exopop/blob/main/document/ms.tex)
- Stated caveats: the importance-sampling estimate "could be a high variance estimator ... depending on the number of independent samples N and the initial choice of" the interim prior, and "the support of p({w_k}|θ) ... is restricted to be narrower than that of" the interim prior — [ms.tex](https://github.com/dfm/exopop/blob/main/document/ms.tex)
- Smoothness: Gaussian-process prior on log step heights (constant mean, anisotropic squared-exponential kernel over bin centres) with log-uniform priors on mean and kernel hyperparameters, which are marginalised; sampler is elliptical slice sampling (adapted from Bovy's BSD code) plus Metropolis–Hastings hyperparameter updates; "for problems with this specific structure, ESS outperforms more traditional MCMC methods commonly employed in astrophysics (e.g. emcee)"; 10^6 steps, last 2×10^5 kept, "≳4000 independent posterior samples" — [ms.tex](https://github.com/dfm/exopop/blob/main/document/ms.tex)
- Also shows the inverse-detection-efficiency (histogram divided by completeness) method is not motivated probabilistically and is biased; calls for catalogues to publish "posterior samples for each target's radius ratio and stellar radius" — [ms.tex](https://github.com/dfm/exopop/blob/main/document/ms.tex)
- Code: `dfm/exopop`, MIT, `code/population.py` "is the meat of the probabilistic model"; scripts `simulate.py`, `main.py`, `results.py`; last commit 2014-09-01; "written specifically for our paper" — [GitHub dfm/exopop](https://github.com/dfm/exopop)

#### Hogg, Myers & Bovy 2010 (ApJ 725, 2166; arXiv:1008.4146), eccentricity distribution
- Takes "as input the likelihood functions for the individual-star eccentricities, or samplings of the posterior probability distributions ... (under a given, uninformative prior)"; "can also be seen as a kind of heteroscedastic deconvolution" applicable to "magnitudes, distances, or photometric redshifts" — [arXiv:1008.4146](https://arxiv.org/abs/1008.4146)
- Importance-sampling caveats: chains are not independent so accuracy does not improve as √N; if the default prior and the population model are very different "the importance-sampling approximation will be noisy", so the interim prior should be uninformative and have support wherever the population might — [arXiv:1008.4146](https://arxiv.org/abs/1008.4146)
- Histogram model: M = 20 bins with a smoothness prior on adjacent log-heights (ε = 2, "a simple smoothness prior (Kitagawa & Gersch 1996)"), noting a GP generalisation allows many bins "but ... sampling highly correlated bin heights is challenging"; a 2-parameter beta-distribution alternative; K = 10^5 posterior samples per star were "almost certainly overkill" — thinning to K = 50 gave "only slightly worse" results and a 2000× speed-up — [arXiv:1008.4146](https://arxiv.org/abs/1008.4146)

### Inferences
- The occurrence-rate formulation gives pastry its selection-aware likelihood: with bins k, rates λ_k (expected numbers, Λ = Σ_k λ_k) and bin detection probabilities Q_k, log L = −Σ_k λ_k Q_k + Σ_i log Σ_k λ_k L̃_ik; with π(Λ) ∝ 1/Λ this marginalises to the normalised form Π_i [Σ_k ρ_k L̃_ik / Σ_k ρ_k Q_k] in fractions ρ (Mandel et al. 2019). What goes into L̃_ik depends on the selection model: if selection is a cut on the same observed data used in the likelihood, L̃_ik = L_ik and Q_k = ∫ S(d) p(d | k) dd (selection enters only the normaliser; Mandel et al. call an extra p_det in the numerator a mistake); if detection is a separate random event with efficiency Q(w) depending on true properties and independent of the catalogued measurement noise (the FM+14 and Blunt et al. assumption, from injection–recovery tests), L̃_ik = Q_k L_ik. pastry should make the user choose explicitly and document both, with both rate and fraction parameterisations.
- Interim-prior correction should be a first-class input (prior density evaluated at samples or per bin); pastry should warn when importance weights are degenerate (e.g. report per-object effective sample sizes), as both Hogg et al. (2010) and Foreman-Mackey et al. (2014) caution.
- GP smoothness over bins with marginalised hyperparameters plus elliptical slice sampling is a proven, simple recipe (FM+14) that pastry can implement without heavy dependencies; the first-difference (random-walk) prior of Hogg et al. (2010) is the cheap special case.
- Zero-likelihood handling is a real pitfall (Blunt et al. scripts); pastry should validate that every object has non-zero support over the bins and fail loudly (or offer an explicit outlier/background component).

## Q4. Other astronomy tools inferring binned/smooth populations from per-object posteriors (general-purpose vs paper code)

### Takeaway
Only a handful of reusable astronomy packages do "population from per-object posteriors": PosteriorStacker (1-D, posterior samples under a flat prior, Gaussian or flat-Dirichlet histogram, nested sampling; CLI script, GPL/AGPL), dftools (R; MML for parametric or step-wise distribution functions with selection), MRExo (fixed beta-density basis with an N×K "C matrix" of error-convolved basis integrals and MLE simplex weights — structurally pastry's model, specialised to exoplanet mass–radius), ePop! (beta-distribution eccentricity populations) and linmix (regression whose covariate distribution is a deconvolved Gaussian mixture). None offers pastry's combination of arbitrary per-object likelihood grids or samples, interim-prior correction, selection, smoothness priors and posterior uncertainty in a scikit-learn/emcee-style API; most are single-purpose, CLI- or script-driven, and maintained by one person.

### Cited Findings

#### PosteriorStacker (Buchner; Baronchelli, Nandra & Buchner 2020, MNRAS 498, 5284, Appendix A)
- "allows deriving sample distributions from posterior distributions from a number of objects"; inputs are "posterior samples of a single parameter, for a number of objects. These need to come from pre-existing analyses, under a flat parameter prior"; models: Gaussian (mean, std) and "a histogram model (using a flat Dirichlet prior distribution)"; "Both models are inferred using UltraNest" — [README](https://github.com/JohannesBuchner/PosteriorStacker)
- Implementation: bins per-object samples into equal-width bins (`np.histogram(row, bins)`), likelihood Σ_i log(binned_i · ρ / N_samples), Dirichlet(1,…,1) prior via an exponential/Gamma transform of unit-cube coordinates for nested sampling — [posteriorstacker.py](https://github.com/JohannesBuchner/PosteriorStacker/blob/main/posteriorstacker.py)
- Usage is a command-line script: `posteriorstacker.py posteriorsamples.txt -80 +80 11 --name="Velocity [km/s]"` (filename, low, high, nbins); outputs per-bin fractions with errors, logZ for both models (model comparison), plots and UltraNest output folders; README advises "Vary the number of samples to check numerical stability!" — [README tutorial](https://github.com/JohannesBuchner/PosteriorStacker)
- PyPI `posteriorstacker` 0.6.4 (2026-09-13; 6 releases since 2021); last commit 2026-10-12; 23 stars; GitHub Actions `make test`; licence inconsistent (README and COPYING say AGPLv3, LICENSE file and PyPI metadata say GPLv3) — [PyPI posteriorstacker](https://pypi.org/project/posteriorstacker/); [GitHub](https://github.com/JohannesBuchner/PosteriorStacker)
- Predecessor: `JohannesBuchner/intrinsicdist1d` ("Estimate population distribution from a sample of posteriors", 2020, 0 stars) — [GitHub search result](https://github.com/JohannesBuchner/intrinsicdist1d)

#### MRExo (Kanodia et al. 2019; Kanodia et al. 2023; method of Ning et al. 2018 as cited in the source)
- Nonparametric joint density of 2–4 observables using "beta density functions as the basis set", "incorporating asymmetric measurement uncertainties and upper limits"; `pip install mrexo`; GPL-3; PyPI 1.1.5 (2023-12-20); last commit 2025-04-13; 5 stars; Read the Docs — [GitHub shbhuk/mrexo](https://github.com/shbhuk/mrexo); [PyPI mrexo](https://pypi.org/project/mrexo/)

### Inferences
- The closest existing analogue to pastry's core is MRExo's internal design (fixed basis, N×K C matrix, simplex MLE, sparse storage, Kish ESS) and PosteriorStacker's histogram mode (posterior samples → per-bin counts → Dirichlet prior → sampled ρ). pastry can be positioned as the general, documented, selection- and interim-prior-aware version of both.
- PosteriorStacker's flat-prior requirement and MRExo's Gaussian/asymmetric-error inputs show the gap pastry fills: accepting (a) dense or sparse likelihood grids L_ik, (b) posterior samples plus the interim prior density, (c) response/template matrices with counts — all mapping to the same internal (N, K) matrix.
- Reporting evidence (logZ) for model comparison, as PosteriorStacker does, is a useful feature for choosing binning/smoothness; pastry could expose marginal-likelihood estimates where cheap (e.g. for conjugate Dirichlet–multinomial via Gibbs/Chib-style or nested sampling).

### Gaps
- I did not find a general-purpose astronomy package for stellar-age or binary-fraction distributions from per-object posteriors; these appear as paper scripts (e.g. Price-Whelan et al. 2020's toy hierarchical inference).
- I could not determine whether the Leja et al. flow was trained on deconvolved or pooled posterior samples.
- GitHub search did not return `vighnesh-nagpal/ePop` (stars unknown; the clone's remote still points there, so it may have been renamed or made unsearchable); `nasa/KeplerPORTs` has 16 stars.

## Q5. Lessons and pitfalls reported by astronomers (selection, Poisson vs multinomial, bins, smoothing, interim priors, scale, calibration)

### Takeaway
The recurring lessons are: (1) never histogram point estimates or divide histograms by completeness — marginalise per-object uncertainty inside a likelihood that includes the selection function, defined on observed quantities, and be explicit about whether selection acts on the measured data or on true properties (this decides whether detection probability appears in each object's term or only in the normaliser); (2) with selection, use a Poisson-process (expected counts) likelihood, which is equivalent to a normalised multinomial only under a 1/N prior on the total; (3) binning and smoothness are modelling choices that need priors or model selection (random-walk/GP priors, CV/AIC/BIC, evidence); (4) interim-prior importance sampling is cheap but can be high-variance and needs adequate support; (5) scale comes from precomputing per-object likelihoods over fixed bins/kernels and parallelising over objects (or GPUs); (6) uncertainty calibration is threatened more by mis-specified errors, contamination/reliability and model systematics than by sampling noise, and point-estimate methods (XD, MML, MLE + bootstrap) under-report it.

### Cited Findings

#### Selection functions and completeness
- Selection functions should be expressed in catalogued (observed) attributes q, must be "defined beyond the domain in q where we actually have cataloged objects", and quality-flag cuts must be checked empirically for their effect on completeness; volume-complete samples are "highly sub-optimal" — [Rix et al. 2021, arXiv:2106.07653](https://arxiv.org/abs/2106.07653)
- Cutting on parallax signal-to-noise discards "a significant fraction of color–magnitude space ... It is by using all of the objects, not only high-SNR ones, that a satisfactory color–magnitude diagram can be inferred" — [Leistedt & Hogg 2017 source, shrinkingparallaxes.tex](https://github.com/ixkael/Starlight)
- Cranmer et al. likewise "include all stars during training, even the low-SNR parallaxes" — [arXiv:1908.08045](https://arxiv.org/abs/1908.08045)
- pygmmis requires a known completeness over the whole feature space with incompleteness "missing at random", and when errors are heteroscedastic and selection non-trivial the user must supply a callback predicting the error covariance at unobserved locations — [pygmmis README](https://github.com/pmelchior/pygmmis)
- Reliability (false-positive) correction can matter more than statistical error: the Kepler Earth-analogue rate drops from 0.034 to 0.015 when corrected — [Bryson et al. 2020, arXiv:1906.03575](https://arxiv.org/abs/1906.03575)
- Unmodelled contaminants bias Hess-diagram fits "toward more old stars and broader metallicity dispersions", hence explicit background templates — [StarFormationHistories.jl CHANGELOG v2.0.0](https://github.com/cgarling/StarFormationHistories.jl/blob/main/CHANGELOG.md)
- The inverse-detection-efficiency histogram is not probabilistically motivated and is biased — [Foreman-Mackey et al. 2014 source](https://github.com/dfm/exopop/blob/main/document/ms.tex)
- Two classic selection mistakes: assuming detection is independent of the data-generating process, which puts an extra p_det(θ) in each object's term and drops the 1/α(λ) normaliser ("every event contributes to a mistake"), or including 1/α(λ) but keeping p_det(θ) in the numerator (error appears once enough events with p_det well below 1 are observed) — [Mandel, Farr & Gair 2019, arXiv:1809.02063](https://arxiv.org/abs/1809.02063)

#### Poisson vs multinomial likelihoods
- Occurrence-rate and Hess-diagram codes use Poisson likelihoods with an expected-count term: FM+14's exp(−∫Γ̂) term; StarFormationHistories.jl's Poisson likelihood ratio; MegaBEAST's Poisson term for the observed number of stars; Blunt et al.'s −Σ completeness × heights × widths — [exopop ms.tex](https://github.com/dfm/exopop/blob/main/document/ms.tex); [SFH.jl docs](https://github.com/cgarling/StarFormationHistories.jl/blob/main/docs/src/fitting/unconstrained.md); [megabeast source](https://github.com/BEAST-Fitting/megabeast/blob/master/megabeast/singlepop_dust_model.py); [sblunt/eccentricities](https://github.com/sblunt/eccentricities)
- Marginalising the Poisson likelihood over the total number N with π(N) ∝ 1/N recovers the selection-normalised (multinomial-type) likelihood; "This correspondence only holds with a 1/N scale-invariant prior" — [Mandel, Farr & Gair 2019, arXiv:1809.02063](https://arxiv.org/abs/1809.02063)
- PosteriorStacker and Leistedt & Hogg use fraction (simplex) parameterisations with Dirichlet priors and no selection — [PosteriorStacker README](https://github.com/JohannesBuchner/PosteriorStacker); [Starlight paper source](https://github.com/ixkael/Starlight)

#### Choice of bins / components and smoothing priors
- Naive deconvolutions "can be very sensitive to histogram binning ... and are unstable to 'ringing'"; Hogg et al. used M = 20 bins with a first-difference smoothness prior and noted that learning ε and M jointly was "beyond our scope" — [Hogg, Myers & Bovy 2010, arXiv:1008.4146](https://arxiv.org/abs/1008.4146)
- FM+14 replace a fixed smoothing strength by a GP with marginalised hyperparameters, so many bins can be used — [exopop ms.tex](https://github.com/dfm/exopop/blob/main/document/ms.tex)
- Fixed tilings need "more components (many of which are zero) but [are] easy to initialize, and also converge quickly" relative to free-form GMMs — [Leistedt & Hogg 2017 source](https://github.com/ixkael/Starlight)
- XD component number is often set heuristically (Anderson et al. fixed K = 128 "with only heuristic analysis"); xdgmm provides BIC/AIC scans; MRExo selects basis degree by CV/AIC/BIC and warns AIC/BIC are for >200 objects — [photoParallax paper.tex](https://github.com/andersdot/photoParallax); [xdgmm.py](https://github.com/tholoien/XDGMM/blob/master/xdgmm/xdgmm.py); [mrexo/fit_nd.py](https://github.com/shbhuk/mrexo/blob/master/mrexo/fit_nd.py)
- Hess-diagram codes choose bins relative to photometric errors (template isochrone points spaced by at most half the photometric error and at most the bin width) and allow masking bins; PANCAKE offers adaptive quadtree/Voronoi binning — [SFH.jl CHANGELOG](https://github.com/cgarling/StarFormationHistories.jl/blob/main/CHANGELOG.md); [arXiv:2505.04534](https://arxiv.org/abs/2505.04534)
- MLE simplex weights often sit on the boundary: "It is normal for some of the coefficients to converge to zero", and posteriors for such coefficients are log-normal-like rather than Gaussian — [SFH.jl docs](https://github.com/cgarling/StarFormationHistories.jl/blob/main/docs/src/fitting/unconstrained.md)

#### Interim priors and posterior-sample inputs
- Importance-sampling caveats: high variance depending on samples and interim prior, support restrictions — [exopop ms.tex](https://github.com/dfm/exopop/blob/main/document/ms.tex); autocorrelated chains, uninformative interim prior needed — [arXiv:1008.4146](https://arxiv.org/abs/1008.4146)
- Few samples suffice when the interim prior is broad: K = 50 per object was "only slightly worse" than 10^5 — [arXiv:1008.4146](https://arxiv.org/abs/1008.4146); for flow deconvolution, samples per star K is "the most significant hyperparameter", training time ∝ K (4 h at K = 32, 16 h at K = 128 on one T4 GPU), and "even with a small number of samples per star, the denoised model is still better than completely ignoring the uncertainty" — [Yan & Sanders 2025, arXiv:2505.16553](https://arxiv.org/abs/2505.16553)
- Practitioners convert posteriors to a common interim prior by importance resampling before population inference (Blunt et al.), or require flat-prior samples (PosteriorStacker) — [sblunt/eccentricities README](https://github.com/sblunt/eccentricities); [PosteriorStacker README](https://github.com/JohannesBuchner/PosteriorStacker)
- FM+14 note catalogue papers rarely publish per-object posterior samples and call them "the most useful data product" — [exopop ms.tex](https://github.com/dfm/exopop/blob/main/document/ms.tex)

#### Scaling to millions of objects
- Leistedt & Hogg handled 1.4 million stars by fixing kernels so the per-star kernel likelihoods g_bs are precomputed once (N independent 1-D integrals) and per-star bin draws are parallel — [Starlight paper source, shrinkingparallaxes.tex](https://github.com/ixkael/Starlight)
- Ritchie & Murray: minibatch EM/SGD on GPU, sublinear training-time scaling; Yan & Sanders report ~1 h for a 2,048-component XD on GPU with that method; CUDAHM: 300,000 objects in ~1 h on one K40c — [arXiv:1911.11663](https://arxiv.org/abs/1911.11663); [arXiv:2505.16553](https://arxiv.org/abs/2505.16553); [arXiv:2105.08026](https://arxiv.org/abs/2105.08026)
- Cranmer et al. trained on 640M Gaia DR2 stars with a flow but only with an approximate (non-convolved) loss — [arXiv:1908.08045](https://arxiv.org/abs/1908.08045)
- StarFormationHistories.jl flattens templates into one matrix so the model is a BLAS matrix–vector product, warning that BLAS threads "do not compose with Julia threads" — [SFH.jl docs fitting intro](https://github.com/cgarling/StarFormationHistories.jl/blob/main/docs/src/fitting/fitting_intro.md)
- Per-object Python loops over samples (as in Blunt et al.'s `calc_likelihood`) do not scale — [run_histogram.py](https://github.com/sblunt/eccentricities)

#### Calibration of uncertainties
- Ignoring source uncertainties gives errors "that grow more severe with increasing sample size" — [Loredo 2004](https://arxiv.org/abs/astro-ph/0409387); bootstrap intervals of the MLE "can be too narrow" while Bayesian intervals are valid — [Kelly, Fan & Vestergaard 2008](https://arxiv.org/abs/0805.2946)
- Over-estimated per-object errors cause "excessive deconvolution" — [Leistedt & Hogg 2017 source](https://github.com/ixkael/Starlight)
- Empirical-Bayes XD priors use the data twice; acceptable only because no single object matters much in large samples — [Anderson et al. 2018 paper.tex](https://github.com/andersdot/photoParallax)
- Variational/IWAE training for flow deconvolution: "the variational bound is not tight, and biases us towards worse prior models", with high variance across training runs — [Dockhorn et al. 2020, arXiv:2006.09396](https://arxiv.org/abs/2006.09396)
- Model systematics (isochrones) can be "2-4 times larger than the random uncertainties" in CMD fitting (citing Dolphin 2012) — [PANCAKE paper, arXiv:2505.04534](https://arxiv.org/abs/2505.04534)
- Derived quantities must be computed per posterior sample to keep inter-bin correlations ("unlike sums of the per-bin star formation rate quantiles") — [SFH.jl CHANGELOG](https://github.com/cgarling/StarFormationHistories.jl/blob/main/CHANGELOG.md)
- Numerical details matter: clamping a Poisson model at eps made the gradient inconsistent with the objective (fixed in SFH.jl 2.0); replacing log(0) by 0 silently drops objects (Blunt et al. scripts); the XD C code can "very rarely decrease the likelihood in a step" — [SFH.jl CHANGELOG](https://github.com/cgarling/StarFormationHistories.jl/blob/main/CHANGELOG.md); [run_histogram.py](https://github.com/sblunt/eccentricities); [XD README](https://github.com/jobovy/extreme-deconvolution)

### Inferences
- pastry should make the selection function an explicit input and convert it to per-bin detection probabilities Q_k = ∫ S(d) p(d | z = k) dd, which requires a model for the noise of undetected objects (the same need that forces pygmmis's covariance callback); it should state which selection model is assumed (cut on observed data: S enters only the normaliser; detection efficiency on true properties independent of the measurements: Q also multiplies each object's term), and offer both Poisson-rate and normalised-fraction parameterisations with the 1/N equivalence documented.
- Default binning should come with a smoothing prior (random-walk/GP on log heights or logit fractions, hyperparameters marginalised) and a diagnostic for bin choice (evidence, held-out likelihood or CV), echoing Hogg et al., FM+14 and MRExo.
- For interim-prior inputs pastry should compute and report per-object importance-sampling effective sample sizes and warn on support mismatch; it should accept samples plus the interim prior density (or log-prior values per sample) and also pre-binned L_ik.
- Calibration tests (simulation-based coverage of bin fractions, including boundary/zero bins and mis-specified errors) are rarely reported by the astronomy tools reviewed; pastry can differentiate itself by shipping them.
- Always return posterior samples of ρ (or of the smooth density) so users can compute derived quantities per sample; Laplace/inverse-Hessian summaries should be optional and flagged as unreliable near zero fractions.

### Gaps
- I found no systematic, published coverage/calibration study comparing XD, Dirichlet–multinomial Gibbs and flow deconvolution on the same astronomical data set (only the `xd_vs_flow` demo and Yan & Sanders's XD comparison).
- I did not compare the Hsu et al. (ABC) and Bryson et al. (Poisson likelihood) Kepler rates quantitatively, so I cannot say how much the inference engine versus the completeness/reliability inputs drives differences.
